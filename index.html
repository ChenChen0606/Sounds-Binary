🎀 Explain It

1. In your own words, how does your app change a sound wave into binary?

My app reads the four numbers and first checks they are valid. Then it works out the period (1000 / frequency, in ms) and the wavelength (343 / frequency, in m). Next it takes the samples at evenly spaced times across one wave. For each sample it finds the wave height with amplitude × sin(2π × i / samples). That height, from -1 to 1, is rounded to a whole level from 0 to (2bits − 1). Finally the level is written as binary with the right number of bits, and all the samples are joined into one line.

2. Run Test A with 2 bits, then 6 bits. Which gives more detail about the wave, and why?

With 2 bits there are only 4 levels, so Test A's samples land on just three of them (10, 11, 11, 11, 10, 00, 00, 00) and the wave looks like big blocky steps. With 6 bits there are 64 levels, and the same samples become 32, 54, 63, 54, 32, 9, 0, 9, which follows the real curve much more closely. More bits means more levels, so each sample is rounded less and the wave keeps more detail.

3. Which test has the longest binary result, and why?

Test A has the longest binary result. It has 8 samples at 3 bits each, so it makes 24 bits. Tests B and C only make 8 bits. The total is always samples × bits, so more samples or more bits makes the binary longer.

4. What was the hardest step to build, and how did you fix it?

The hardest part was rounding to the right level. The sine of some angles came out as a tiny number like 0.0000000000000001 instead of exactly 0, which sometimes pushed a level to the wrong side of a rounding point. I fixed it by rounding the amplitude to 9 decimal places before finding the level. After that my results matched the Check Your Work table.
